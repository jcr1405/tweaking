## 1. PURPOSE & ARCHITECTURAL OBJECTIVE

This specification defines the intelligence and execution architecture for **Backend Phase 2A** of our Persistent Intelligent Presence.

### Core Architectural Invariant:
> **Gemini is the reasoning provider. Our Presence Agent Engine owns execution.**

We do not allow the Gemini SDK to become our agent runtime, nor do we allow model-generated function calls to execute automatically. The engine deterministically controls:
- Conversation identity and lineage.
- Offline context reconstruction from local SQLite databases.
- Streaming event normalisation and dispatch.
- Agent turn state transitions and cancellation.
- Tool discovery, schema validation, and 4-tier permission enforcement.
- Dual-journal transactional persistence.

## 3. PROVIDER ABSTRACTION (`IModelProvider`)

To ensure Gemini remains 100% replaceable by Anthropic Claude, OpenAI, or local models (Ollama/llama.cpp), model interactions are mediated by `IModelProvider`:

```python
class IModelProvider(ABC):
    """Provider-independent interface for model inference."""

    @property
    @abstractmethod
    def provider_name(self) -> str:
        pass

    @abstractmethod
    def generate_stream(
        self,
        system_prompt: str,
        messages: List[Dict[str, Any]],
        tools: Optional[List[Dict[str, Any]]] = None,
        cancellation_token: Optional[Any] = None
    ) -> Iterator[ModelStreamChunk]:
        """Streams normalized response events from the inference provider."""
        pass
```

### 3.1 Normalized Stream Chunk Schema (`ModelStreamChunk`)
All provider-specific SDK response objects are mapped into a standardized `ModelStreamChunk`:
- `text_delta`: Incremental text fragment generated by the model.
- `thinking_status`: Operational status indicator (e.g. "reasoning", "calling_tool").
- `tool_calls`: List of requested tool invocations: `[{"call_id": "...", "name": "...", "args": {...}}]`.
- `usage`: Token consumption metadata (`prompt_tokens`, `completion_tokens`, `cached_tokens`).
- `finish_reason`: Completion reason (`STOP`, `TOOL_CALL`, `MAX_TOKENS`, `SAFETY`).

## 4. API KEY & CREDENTIAL SECURITY

1. **Environment Configuration:** The API key is read exclusively from the `GEMINI_API_KEY` environment variable.
2. **Zero-Leakage Invariant:** The key is never logged, never persisted to SQLite, never written to `transcript.jsonl`, never stored in exception strings, and never committed to source control.
3. **Secret Redaction Pipeline:** All logs pass through `SanitizingFilter` ([runtime/logging.py](file:///c:/Users/chait/OneDrive/Documents/projects/tweaking/runtime/logging.py)), which redacts any bearer tokens or 39-character Google API keys.
4. **Deferred Provisioning:** The user supplies their API key in their local shell environment before running live queries (`$env:GEMINI_API_KEY = "..."`). In automated testing and local execution, tests run against `FakeModelProvider` with zero quota consumption.

## 5. AGENT EXECUTION ENGINE & TURN LIFECYCLE

The `AgentExecutor` coordinates the multi-step execution loop across user inputs, context reassembly, model inference, tool execution, and dual-journal persistence:

```
[User Input Received]
         │
         ▼
[1. Resolve Conversation & Persist USER_INPUT Step (SQLite + JSONL)]
         │
         ▼
[2. Reconstruct Local Context (ContextAssembler - Steps + Summary)]
         │
         ▼
[3. Resolve Registered Tools (ToolRegistry - L0/L1 Tools)]
         │
         ▼
[4. Dispatch to IModelProvider.generate_stream()]
         │
         ├─── Stream TEXT_DELTA ───> Emit Engine Event & Yield to UI
         │
         ▼
[5. Model Requests Tool Call?]
         │
         ├─── YES ──> [Manual Tool Authorization Gate]
         │                 │
         │                 ├── Validate Tool ID in Registry
         │                 ├── Validate Input Schema
         │                 └── PermissionBoundary.authorize()
         │                         │
         │                         ├── REJECTED ──> Emit Tool Error to Model
         │                         │
         │                         └── GRANTED ───> Execute Handler
         │                                               │
         │                                         Persist TOOL_CALL & TOOL_RESULT (SQLite)
         │                                               │
         │                                         Feed Result to Model & Loop back to Step 4
         │
         └─── NO  ──> [Final Assistant Response Reached]
                           │
                     Persist AGENT_TURN Step (SQLite + JSONL)
                           │
                     Update GlobalSummaryManager (Step count, FTS5 Index)
                           │
                     Emit TURN_COMPLETED Event
```

### 5.1 Agent Lifecycle State Machine
Execution state transitions are explicit:
`CREATED -> RUNNING -> WAITING_FOR_MODEL -> STREAMING -> TOOL_PENDING -> TOOL_RUNNING -> COMPLETED | FAILED | CANCELLED | INTERRUPTED`

### 5.2 Turn Cancellation Semantics
- An active turn can be aborted via `cancellation_token.cancel()`.
- The provider stream terminates immediately.
- Pending tool executions are aborted.
- Completed steps remain durably recorded in SQLite with `status = INTERRUPTED` or `CANCELLED`.
- No uncommitted partial state corrupts the conversation.

## 6. MANUAL TOOL EXECUTION & SECURITY BOUNDARIES

> **Rule:** SDK automatic tool execution is explicitly disabled. Every function call requested by Gemini is treated as an untrusted proposal.

### 6.1 Tool Execution Pipeline
```
Gemini Function Call {"name": "presence.search_conversations", "args": {"query": "wal"}}
             │
             ▼
[ToolRegistry: Lookup tool definition]
             │
             ▼
[JSON Schema Validation: Validate arguments]
             │
             ▼
[PermissionBoundary.authorize(action, tier)]:
 - L0_OBSERVE: Autonomous execution permitted.
 - L1_RECOMMEND: Autonomous advisory output.
 - L2_EXECUTE_REVERSIBLE: Autonomous reversible actions.
 - L3_PROTECTED: Fail-closed; requires explicit user consent token.
             │
             ▼
[Execute registered Python handler within try/except block]
             │
             ▼
[Record step in SQLite & transcript.jsonl]
             │
             ▼
[Return structured output envelope to Gemini]
```

### 6.2 Initial Built-In L0 Tools
1. `presence.get_runtime_status`: Reports runtime uptime, state, and memory footprint (`L0_OBSERVE`).
2. `presence.get_conversation_info`: Reports title, step count, and metadata of the active conversation (`L0_OBSERVE`).
3. `presence.search_conversations`: Searches historical discussions via SQLite FTS5 (`L0_OBSERVE`).

---

## 7. DUAL-JOURNAL INTEGRATION & WRITE ORDERING

1. **Step Commit First:** When an action occurs (user prompt, tool result, or model answer), the strongly-typed `Step` is committed transactionally to `conversations/<uuid>.db` (`steps` table).
2. **Streaming Event Broadcast:** Streaming deltas are emitted to `transcript.jsonl` and the in-memory `EventBus`.
3. **Reconciliation Guarantee:** If the engine process crashes during response generation, SQLite contains the last valid completed step. On reboot, `ContextAssembler` re-hydrates state accurately.
